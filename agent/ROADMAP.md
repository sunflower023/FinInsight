# Roadmap

## P0：先让基础可信

- 建立 Catch2/CTest 测试目标，覆盖 IndicatorEngine、Lexer/Parser、DataHub。
- 修复 CMakePresets 的本机路径问题，记录 Qt/编译器版本。
- 为网络请求增加统一错误类型、取消和超时语义。
- 明确 UI 加载状态、重试和无网络时的缓存行为。

## P1：完成一条有含金量的业务闭环

- DSL 绑定历史 K 线，按时间序列求值。
- 建立模拟投资账本：虚拟账户、现金、模拟成交、持仓成本、已实现/未实现盈亏、手续费和交易日校验。
- 支持任意历史时点的假设交易：输入标的、买入日期、金额和结束日期，计算收益率、最大回撤，并与可选基准比较。
- 将交易记录、持仓与实验配置迁移到 SQLite，确保计算结果可复现。
- 用异步多源请求实现真正的 first-valid + 取消剩余任务。

## P1.5：模拟投资实验室深化

- 增加组合层能力：现金管理、仓位限制、定投、再平衡和组合净值曲线。
- 增加风险与归因指标：波动率、夏普比率、最大回撤、集中度和基准超额收益；明确指标的计算口径与数据范围。
- 正确处理行情时间序列边界：交易日、时区、复权价格、缺失数据、停牌及公司行动。首期应明确不支持的市场和公司行动，不能静默给出错误结果。
- 为账本、成交规则、收益与回撤计算提供离线 fixture 和单元测试；回测/实验输入必须版本化，结果须可复算。

## P2：行为复盘与 Agent（在账本和指标可信后）

- 基于模拟交易记录识别可量化的行为模式，例如频繁交易、追涨杀跌、过度集中和忽视回撤。
- Agent 的每项结论必须附带交易记录、指标或时间段证据，并区分事实、推断和教育性建议。
- 默认提供风险提示与模拟免责声明；Agent 不提供确定性荐股、收益承诺或自动下单能力。

## P3：工程化

- 增加 CI（Windows 构建、单元测试、格式检查）。
- 增加离线 fixture，避免测试依赖 Yahoo/EastMoney 在线服务。
- 对指标计算和 JSON 解析增加基准测试与故障注入。
- 将 UI、数据源和策略引擎拆成更容易独立测试的 target。
